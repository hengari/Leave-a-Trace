# 留痕 · 后端架构与数据库

> 版本：v1.0 · 2026-08-07

## 1. 架构总览

```
浏览器 / 局域网设备
        │  HTTP（同源）
        ▼
scripts/serve.mjs  ── 静态站点（src/web） ──► 前端页面
        │
        ├── GET/PUT /api/state ──► SQLite app_state 表（状态 JSON）
        │
        ├── POST/GET/DELETE /api/files ──► files 表（元数据）
        │                                    └─► data/files/<id>/（文件本体）
        └── GET /api/health / /api/files ──► 探活 / 文件列表

Electron 桌面端（main.cjs）
        │  IPC（db:* / file:*）
        ▼
electron/trace-db.cjs（与 Web 后端共用）──► SQLite trace.db + data/files/
```

设计原则：

- **零外部依赖**：只使用 Node 内置模块（`node:http`、`node:sqlite`、`node:fs` 等），不需要 npm install、不需要单独安装数据库服务。
- **单用户本地优先**：数据全部落在本机 `data/` 目录，复制该目录即可整体迁移；局域网访问共用同一份数据。
- **前端向后兼容**：浏览器直接双击 HTML 打开时（非 http 协议）自动回退到 localStorage 模式；Electron 桌面端通过 IPC 直连统一数据库。

## 2. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 运行环境 | Node.js ≥ 22.5 | 内置 `node:sqlite`（DatabaseSync） |
| Web 服务 | `node:http` | 无需 Express 等框架 |
| 数据库 | SQLite（WAL 模式） | 单文件、零运维、支持并发读写 |
| 文件存储 | 文件系统 `data/files/<uuid>/` | 文件本体落盘，数据库只存元数据 |
| 桌面端 | Electron 35（Node 22）+ IPC | 主进程直连 SQLite，与 Web 共用 `trace-db.cjs` |
| 前端 | 原生 fetch / IPC 接入 | 服务模式 / 桌面模式 / localStorage 回退三模式 |

## 3. 数据目录

```
data/
├── trace.db          ← SQLite 数据库（含 -wal / -shm 伴随文件）
└── files/
    └── <文件UUID>/
        └── <原文件名>  ← 上传文件本体
```

`data/` 已加入 `.gitignore`，不会进入版本库。

## 4. 数据库设计

### 表 `app_state`（应用状态，单行文档存储）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PRIMARY KEY | 恒为 1（单行） |
| data | TEXT | 完整状态 JSON（meta / days / files / monthlyReports / settings） |
| updated_at | TEXT | 最后写入时间（ISO 8601） |

任务、打卡、月报、设置等业务数据统一存于状态 JSON，与前端现有数据结构完全一致，避免大面积重写前端模型。

### 表 `files`（文件元数据）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT PRIMARY KEY | UUID（也是磁盘目录名） |
| name | TEXT | 原文件名（入库时清洗非法字符） |
| ext | TEXT | 扩展名（小写） |
| mime | TEXT | 按扩展名推断的 MIME |
| size | INTEGER | 文件字节数 |
| date | TEXT | 归属日期（YYYY-MM-DD） |
| tags | TEXT | 标签 JSON 数组 |
| imported_at | TEXT | 导入时间（ISO 8601） |
| storage_path | TEXT | 磁盘绝对路径（仅服务端使用，不出现在 API 响应中） |
| created_at | TEXT | 记录创建时间 |

文件**本体**与**元数据**分离：删除文件时同时删除数据库记录与磁盘目录。

## 5. REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 探活，返回服务与数据库路径 |
| GET | `/api/state` | 获取完整状态（无数据时 `data: null`） |
| PUT | `/api/state` | 覆盖保存完整状态（校验 meta / days） |
| GET | `/api/files` | 文件元数据列表 |
| POST | `/api/files?name=&date=&tags=&importedAt=` | 上传文件（请求体为文件二进制），返回文件记录 |
| GET | `/api/files/:id` | 下载文件（`Content-Disposition: attachment`） |
| GET | `/api/files/:id/raw` | 读取文件内容（inline，供前端预览） |
| DELETE | `/api/files/:id` | 删除记录与磁盘文件 |

限制：状态体 ≤ 200MB；单文件 ≤ 500MB。

## 6. 前端接入方式

`src/web/js/app.js` 通过 `location.protocol` 判断模式：

- **服务模式**（`http://` / `https://`，即通过 start.bat 或局域网访问）：
  - 启动时 `GET /api/state` 拉取服务器数据；服务器为空时回退读取 localStorage（老数据自动迁移，首次 `save()` 即写回服务器）。
  - `save()` 在写 localStorage 的同时，300ms 防抖 `PUT /api/state`。
  - 文件导入直接 `POST /api/files` 上传二进制；预览走 `/api/files/:id/raw`；下载走 `/api/files/:id`；删除调用 `DELETE /api/files/:id`。
  - 月度汇总生成的 Markdown 同样上传归档到服务器文件库。
- **本地模式**（`file://` 直接打开 / Electron）：保持原行为，localStorage 存取 + `dataUrl` 内嵌。

Electron 桌面端（`window.traceDesktop` IPC）：

- `db:getState` / `db:putState`：主进程直连 SQLite（同一 `app_state` / `files` 表）
- `file:upload` / `file:getDataUrl` / `file:delete`：文件经主进程落盘 `data/files/<uuid>/`
- 数据目录：开发运行 = 项目 `data/`；打包运行 = `%APPDATA%\留痕\data`；可用环境变量 `TRACE_DATA_DIR` 覆盖

## 7. 部署

```powershell
# 本机
node scripts/serve.mjs
# 或一键启动（推荐）
start.bat
```

局域网访问：其他设备通过 `http://<本机IP>:8787/` 打开（启动日志会打印本机 IP）。

桌面版：`npm start` 开发运行，`npm run dist` 生成安装包（`release\留痕-1.0.7-setup.exe`）。

## 8. 备份与迁移

- 整体备份：停止服务后复制整个 `data/` 目录；或直接在页面“备份与恢复”导出 JSON（含任务与文件元数据，文件本体在服务端）。
- 迁移：把 `data/` 目录拷到新机器同位置即可。
- 桌面版：开发运行复制项目 `data/`；打包运行复制 `%APPDATA%\留痕\data`（或 `TRACE_DATA_DIR` 指向的目录）。
- 注意：JSON 备份不包含服务器上的文件本体（浏览器模式的内嵌文件除外），如需完整迁移请复制 `data/files/`。

## 9. 安全与注意事项

- 当前为无鉴权的局域网原型服务：仅建议在可信内网使用；如需公网暴露，应增加登录鉴权与 HTTPS。
- 文件 ID 仅接受 `[A-Za-z0-9_-]`，文件名入库时清洗 `\ / : * ? " < > |` 等字符，防止路径穿越。
- SQLite 使用 WAL 模式，进程异常退出后数据库仍有恢复能力。
